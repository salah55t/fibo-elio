# 🌊 Fibo-Elio — بوت موجة إليوت + مستويات فيبوناتشي

مشروع منفصل ب**استراتيجية واحدة فقط**: موجات إليوت الدافعة + مستويات فيبوناتشي، بمنطق
**المشروع الأصلي المنقول حرفيًا** — [dtwijesekara/Elliott_Waves_Algo_TradingBot](https://github.com/dtwijesekara/Elliott_Waves_Algo_TradingBot) (MIT).

> كل الاستراتيجيات الأخرى من المشروع السابق (crypto-bot-v9) حُذفت بنيويًا بطلب المالك.
> **الوضع ورقي دائمًا** — البوت لا يرسل أي أمر حقيقي إلى المنصة إطلاقًا.

## 🧠 الاستراتيجية — كما في الأصل قبل الاقتباس

### 1) كشف الموجات (engine/pattern_detector.py — منقول حرفيًا)
- زيجزاج بنسبة انعكاس (آلة حالة ثلاثية الأطوار) على أسعار **الإغلاق**
- محاور بأسعار High/Low الحقيقية، المحور الأخير غير المؤكد، تناوب صارم، فصل زمني ≥ شمعتين
- نافذة منزلقة من 6 محاور P0–P5 لكل دافع مرشح

### 2) القواعد الصارمة الثلاث (engine/wave_validator.py — منقول حرفيًا)
| القاعدة | الشرط |
|---|---|
| W2 لا تكسر أصل W1 | P2 يجب أن يبقى فوق P0 (صاعدة) |
| W3 ليست الأقصر | \|P3−P2\| > min(\|P1−P0\|, \|P5−P4\|) **و** تكسر قمة W1 |
| W4 لا تتداخل مع W1 | P4 يبقى فوق P1 (صاعدة) |

### 3) فيبوناتشي (engine/fibonacci.py — منقول حرفيًا)
- تصحيح: 0.236 / 0.382 / 0.500 / 0.618 / 0.786 / 0.886 — امتداد: 1.0 → 3.414
- مناطق المؤلف المميزة: W2 = 0.382–0.618 · W3 = 1.618–2.618 · W4 = 0.236–0.382 · W5 = 0.382–0.618 من W1

### 4) التداول (نفس تدفق execute_wave_setup الأصلي)
| العنصر | القيمة الأصلية |
|---|---|
| الدخول | **أمر معلّق** عند حد 0.382 لتراجع الموجة 3 (entry_zone_low) |
| الوقف | **بنيوي** خلف أصل الموجة 1: P0 − 0.1% |
| الهدف | **امتداد فيبوناتشي 1.618 للموجة 1** من قاع الموجة 2 |
| الاختيار الأفضل | +1 لمنطقة W2 المثالية (0.382–0.886) +1 لمنطقة W4 (0.236–0.5)، ثم الأحدث |
| الإلغاء | إغلاق خلف P0 يبطل العدّ، أو انقضاء 3 شموع كشف دون ملء |
| الاتجاه | الكشف للاتجاهين — التنفيذ ورقي للصاعدة (سبوت شراء فقط)، والهابطة تُعرض في اللوحة |

## ⚙️ الإعدادات (متغيرات البيئة)

| المتغير | الافتراضي | الشرح |
|---|---|---|
| `DEVIATION_THRESHOLD` | `0.006` | نسبة انعكاس الزيجزاج — 0.6% وفق جدول معايرة المؤلف لفريم 1h (0.3–0.6%) |
| `SIGNAL_TIMEFRAME` | `1h` | فريم الكشف |
| `ENTRY_TIMEFRAME` | `15m` | فريم تنفيذ الملء/الوقف/الهدف |
| `MAX_OPEN_TRADES` | `3` | أقصى صفقات متزامنة |
| `RISK_PCT_PER_TRADE` | `1.0` | مخاطرة الصفقة % من الرصيد الورقي |
| `PENDING_MAX_CANDLES` | `3` | صلاحية الأمر المعلق بشموع الكشف |
| `PAPER_BALANCE` | `10000` | الرصيد الورقي الابتدائي |
| `OHLCV_LIMIT` | `500` | عدد الشموع لكل فحص |
| `BINANCE_API_KEY/SECRET` | فارغ | اختياريان — الشموع العامة تكفي للورقي |
| `DATABASE_URL` | فارغ | PostgreSQL (Render) — وإلا SQLite محلي |
| `DASHBOARD_USERNAME/PASSWORD` | فارغ | حماية اللوحة بـ Basic Auth |
| `TELEGRAM_BOT_TOKEN/CHAT_ID` | فارغ | إشعارات تلجرام |

جدول معايرة المؤلف الأصلي (`deviation_threshold`):

| فريم | النطاق | ملاحظات |
|---|---|---|
| 5m | 0.6–1.0% | سكالب قياسي |
| **15m** | **0.4–0.8%** | فريم الدخول في هذا البوت |
| **1h** | **0.3–0.6%** | فريم الكشف الافتراضي |
| 4h | 0.2–0.5% | سوينغ |

قاعدة المؤلف: إشارات كثيرة خاطئة → ارفع النسبة. موجات صالحة تفوت → اخفضها.

## 🚀 التشغيل محليًا

```bash
pip install -r requirements.txt
python vnz.py            # اللوحة على http://localhost:10000
```

## ☁️ النشر على Render
1. أنشئ Web Service جديدًا من المستودع `salah55t/fibo-elio`
2. Build: `pip install -r requirements.txt` — Start: `python vnz.py` — Health: `/health`
3. أضف متغيرات البيئة من الجدول أعلاه (`DASHBOARD_USERNAME=admin`, `DASHBOARD_PASSWORD=...`)
4. اختياري: اربط PostgreSQL مجاني وأضف `DATABASE_URL` ليبقى التاريخ بعد إعادة النشر
